## 📈 性能分析

### 帧率 vs 目标

```
目标帧率: 30 fps ██████████████████████████████ 100%
实测帧率: 24.25 fps ████████████████████████░░░░ 80.8%

差距: 5.75 fps (19.2%)
```

### 可能的原因

1. **USB 带宽限制**
   - USB 2.0 理论带宽: 480 Mbps
   - MJPEG 640x480 @ 30fps 需求: ~100-150 Mbps
   - 实际可用带宽可能受限

2. **摄像头硬件限制**
   - 某些 USB 摄像头在高帧率下会自动降低质量
   - 曝光时间可能影响最大帧率

3. **编码处理时间**
   - Hobot X5 硬件编码器需要 ~3ms/帧
   - 加上 USB 传输时间，总延迟约 40-44ms

4. **系统负载**
   - CPU 调度延迟
   - ROS2 通信开销

### 帧间隔分布

```
帧间隔范围      占比        说明
-----------     ------      ------
0.039-0.041s    ~60%        正常帧间隔（对应 24-25 fps）
0.041-0.044s    ~30%        轻微延迟
0.015-0.039s    ~5%         快速帧（可能是缓冲释放）
0.044-0.064s    ~5%         偶发延迟（系统调度）
```

## 💡 优化建议

### 当前状态评估

✅ **良好**: 24.25 fps 对于实时监控已经足够
✅ **稳定**: 帧率波动很小，无明显丢帧
✅ **低延迟**: 帧间隔稳定在 40ms 左右

### 如需提升到 30 fps

#### 方案 1: 降低图像质量
```python
# 在 hobot_usb_cam 节点中调整 JPEG 质量
# 默认质量可能较高，降低可以提升帧率
jpg_quality: 60 → 50 或 40
```

#### 方案 2: 检查 USB 连接
```bash
# 确认使用 USB 2.0 或更高版本
lsusb -t

# 预期输出应显示 high speed (480Mbps) 或 super speed (5Gbps)
```

#### 方案 3: 优化系统调度
```bash
# 提高 ROS2 进程优先级
sudo renice -10 $(pgrep -f hobot_usb_cam)

# 使用实时内核（如果可用）
```

#### 方案 4: 调整分辨率
```python
# 如果不需要 640x480，可以降低到更小分辨率
usb_image_width: 640 → 480
usb_image_height: 480 → 360
# 预期帧率可提升至 30+ fps
```

### 不建议的优化

❌ **不推荐**: 强制设置更高帧率参数
- 摄像头硬件可能不支持
- 可能导致图像质量下降或不稳定

❌ **不推荐**: 使用软件编码替代硬件编码
- CPU 占用率会大幅增加
- 延迟会增加
